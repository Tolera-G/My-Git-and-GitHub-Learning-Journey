# Lesson 52: GitHub Teams, Roles, and Permissions

## Overview

GitHub Teams allow organizations to group members according to their responsibilities and manage repository access collectively.

Teams simplify collaboration by allowing administrators to assign permissions to groups instead of managing every developer individually.

## Learning Objectives

- Understand GitHub Teams.
- Create and manage teams.
- Add organization members to teams.
- Understand team roles.
- Understand repository permissions.
- Connect teams to repositories.

## 1. GitHub Teams

A GitHub Team is a group of organization members who share responsibilities and repository access.

Examples:

- Frontend Team
- Backend Team
- Mobile Team
- Design Team

## 2. Creating a Team

1. Open the GitHub Organization.
2. Navigate to Teams.
3. Select New team.
4. Enter a team name.
5. Add a description.
6. Choose team visibility.
7. Create the team.

## 3. Adding Members

1. Open the team.
2. Navigate to Members.
3. Select Add a member.
4. Search for an organization member.
5. Select the member.
6. Confirm the addition.

## 4. Team Roles

| Role | Responsibility |
|---|---|
| Team Maintainer | Manages team settings and membership |
| Team Member | Participates in the team |

A Team Maintainer is different from an Organization Owner.

## 5. Repository Permissions

GitHub provides five main repository permission levels.

| Permission | Description |
|---|---|
| Read | View and clone repositories |
| Triage | Manage issues and pull requests |
| Write | Contribute code |
| Maintain | Manage repository operations |
| Admin | Full repository administration |

## 6. Connecting Teams to Repositories

1. Open the organization repository.
2. Navigate to Settings.
3. Open Collaborators and teams.
4. Select Add teams.
5. Choose the desired team.
6. Assign the appropriate repository permission.
7. Confirm the changes.

## 7. Team Visibility

GitHub supports:

- Visible teams: Discoverable by organization members.
- Secret teams: Team details and membership are restricted to permitted viewers.

## 8. Organization Roles vs Team Roles vs Repository Permissions

| Concept | Purpose |
|---|---|
| Organization role | Controls organizational responsibilities |
| Team role | Defines responsibilities within a team |
| Repository permission | Controls repository access |

## Practical Exercise

1. Create a Frontend Team.
2. Create a Backend Team.
3. Add organization members.
4. Assign team maintainers where appropriate.
5. Connect Frontend Team to a repository.
6. Grant Write permission.
7. Explore all five repository permission levels.

## Key Takeaways

- Teams organize developers by responsibility.
- Team maintainers manage team-level activities.
- Repository permissions determine what developers can do.
- Teams can receive repository access collectively.
- Apply the principle of least privilege: give members only the access they need.
