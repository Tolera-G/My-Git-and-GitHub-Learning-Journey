# Lesson 53: Understanding GitHub Issues

## Overview

GitHub Issues are tools for tracking work within a repository.

Development teams use Issues to report bugs, suggest features, discuss improvements, and organize tasks.

## Learning Objectives

- Understand GitHub Issues.
- Create new issues.
- Report software bugs.
- Suggest new features.
- Assign issues to developers.
- Comment on issues.
- Close completed issues.
- Understand the relationship between Issues and Pull Requests.

## 1. What Are GitHub Issues?

GitHub Issues provide a shared workspace for tracking development tasks and discussing problems.

Common uses include:

- Bug reports
- Feature requests
- Improvements
- Development tasks
- Documentation updates

## 2. Main Components of an Issue

| Component | Purpose |
|---|---|
| Title | Describes the task |
| Description | Explains the task in detail |
| Assignees | Identifies responsible developers |
| Labels | Categorizes issues |
| Milestones | Groups issues toward a goal |
| Comments | Supports team discussions |
| Status | Indicates whether an issue is open or closed |

## 3. Creating an Issue

1. Open a GitHub repository.
2. Navigate to Issues.
3. Select New issue.
4. Enter an informative title.
5. Write a detailed description.
6. Submit the issue.

## 4. Types of Issues

### Bug Reports
Used to report unexpected software behavior.

### Feature Requests
Used to suggest new functionality.

### Tasks
Used to organize development activities.

### Improvements
Used to enhance existing functionality.

## 5. Issue Conversations

Developers can use comments to:

- Ask questions.
- Share progress.
- Suggest solutions.
- Discuss implementation approaches.

## 6. Assigning Issues

An issue can be assigned to one or more developers.

To assign an issue:

1. Open the issue.
2. Find Assignees.
3. Select the appropriate developer.

## 7. Closing Issues

Issues can be closed manually using the Close issue button.

GitHub also supports automatic issue closure through Pull Requests.

Examples of closing keywords:

- Fixes #1
- Closes #1
- Resolves #1

When used in a supported Pull Request context, the linked issue is automatically closed after merging into the default branch.

## 8. Issues vs Pull Requests

| Issues | Pull Requests |
|---|---|
| Track tasks | Propose code changes |
| Report bugs | Review proposed changes |
| Suggest features | Merge code |
| Organize discussions | Facilitate code review |

An Issue describes what needs to be done, while a Pull Request proposes the code changes needed to accomplish it.

## Practical Exercise

1. Create an issue titled Fix homepage navigation responsiveness.
2. Create an issue titled Add dark mode support.
3. Create an issue titled Improve README documentation.
4. Add comments to an issue.
5. Assign an issue to a teammate.
6. Explore closing an issue.

## Key Takeaways

- Issues help teams organize development work.
- Issues can represent bugs, features, tasks, and improvements.
- Assignees identify responsible developers.
- Comments support team discussions.
- Issues can be closed manually or automatically through linked Pull Requests.
- Issues and Pull Requests serve different but complementary purposes.
